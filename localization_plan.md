# STS Stat Viewer Localization Plan

> **Status**: Proposed plan as of 2026-02-16.
> **Goal**: Add full modular app localization while keeping functionality unchanged.
> **Critical requirement**: Prefer official Slay the Spire terminology wherever available, then use controlled DeepL generation for missing translations, and track human-vs-AI verification per locale.

---

- [x] Phases are ordered by dependency and risk.

## Non-negotiable constraints

- [x] App behavior must remain functionally identical (data loading, filtering, graph logic, update flow, settings behavior). — Verified via build + typecheck.
- [x] English (`en`) remains the source locale and fallback of last resort. — Hardcoded in i18n runtime.
- [x] Non-English locales default to **AI-generated/unverified** until explicitly human-verified. — Enforced by translate.ts metadata generation.
- [x] Canonical Slay the Spire names (cards/relics/characters/etc.) must not be overwritten by generic machine translation when official equivalents are available. — Protected in translate.ts + canonical term lock CI check.
- [x] Unknown/modded game terms must fail safe by falling back to original source text (no destructive guessing). — Extract script preserves unknown terms; runtime falls back to English.

## Architecture decisions

### A. Localization framework and format

- [x] Use a **typed localization system** for Svelte/TS (recommended: `typesafe-i18n`-style generated typings) to prevent missing/invalid keys at compile time.
- [x] Organize translation resources by namespace/module (example: `common`, `dashboard`, `graphs`, `settings`, `errors`, `update_manager`, `game_terms`).
- [x] Keep English base messages as single source of truth.
- [x] Use key-based translations (no runtime free-form English-as-key).

### B. Message capabilities

- [x] Support interpolation with explicit placeholders (e.g., `{count}`, `{version}`).
- [x] Support pluralization rules using CLDR-compatible message formatting. — `tp` store using `Intl.PluralRules` with pipe-separated forms.
- [x] Enforce escaping/safe rendering defaults for interpolated values.

### C. Locale fallback strategy

- [x] Runtime fallback chain: `requested locale -> language base (if region variant) -> en`.
- [x] Missing keys in non-English locale automatically resolve to English.
- [x] Missing-key reporting enabled in development and CI. — Dev-mode console warning with deduplication in `t` store; CI via `i18n:validate`.

### D. Canonical game-terms strategy

- [x] Treat official STS localization files as canonical term source when present. — `extract-canonical.ts` reads from game JAR.
- [x] Maintain a generated canonical glossary per locale from game assets. — Generated to `src/lib/i18n/canonical/<locale>.json`.
- [x] Enforce precedence: `canonical STS term > manually approved app override > DeepL translation > English fallback`. — `translate.ts` protects canonical terms during DeepL translation.

### E. AI vs human verification model

- [x] Introduce translation provenance metadata per locale.
- [x] Default all non-English locales to `ai_unverified`.
- [x] Add explicit workflow to move locale status to `human_verified` only after full review. — CI validation enforces reviewed_by, reviewed_at, and 100% coverage.
